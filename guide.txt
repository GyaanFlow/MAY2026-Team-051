1. PROJECT OVERVIEW
========================================================================

This is a Flask + Flask-RESTful + JWT based REST API for a Library
Membership Management System, now extended with a Booking and Seat
Management module. It has three user roles:

  - Admin   : manages staff, membership plans, approves/rejects memberships
  - Staff   : registers new students, views student profiles, manages bookings
  - Student : views/edits own profile, resets password, books seats

Tech stack:
  - Flask 3.0.3
  - Flask-RESTful 0.3.10
  - Flask-SQLAlchemy 3.1.1
  - Flask-JWT-Extended 4.6.0
  - Werkzeug 3.0.3
  - Flask-CORS 4.0.1
  - SQLite (default local database, file: app.db)

2. PROJECT STRUCTURE
========================================================================

seProject/
|-- app.py                  -> creates Flask app, registers all routes, seeds data
|-- config.py               -> app config (secret keys, database URL, JWT expiry)
|-- models.py               -> User, MembershipPlan, Student, Seat, Booking
|-- utils.py                -> admin_required and staff_or_admin_required decorators
|-- requirements.txt        -> pinned dependency versions
|-- resources/
|     |-- auth.py               -> login
|     |-- staff.py              -> admin managing staff accounts
|     |-- membership.py         -> admin managing membership plans (price only)
|     |-- students.py           -> student create/list/approve/reject/disapprove
|     |-- profile.py            -> logged-in user's own profile + password reset
|     |-- staff_students.py     -> staff registers new student, views student profile
|     |-- admin_memberships.py  -> admin membership approval workflow
|     |-- seats.py              -> real-time seat availability (Story 3.1)
|     |-- bookings.py           -> create/modify/cancel/history/walk-in (Stories 3.2–3.6)

3. HOW TO RUN THE PROJECT (STEP BY STEP)
========================================================================

Step 1 - Install dependencies
    pip install -r requirements.txt

Step 2 - Delete old database if schema changed
    Windows:
        del app.db
    or if it is inside an instance folder:

4. AUTHENTICATION FLOW
========================================================================

Every route except /auth/login requires a Bearer token.

Step 1: Login
    POST /api/auth/login
    Body (JSON):
    {
      "username": "admin",
      "password": "admin123"
    }

    Response:
    {
      "access_token": "xxxxx.....",
      "user": { ...user fields... }
    }

Step 2: Use token on every other request
    Header:
    Authorization: Bearer <access_token>

Token expires after 8 hours.

Roles embedded in JWT: role = Admin / Staff / Student.
Decorators in utils.py:
    admin_required           -> Admin only
    staff_or_admin_required  -> Staff or Admin

Booking APIs (seats.py, bookings.py) use jwt_required() for general
access; staff-only functions (daily overview, walk-in) also use
staff_or_admin_required. Modify/cancel additionally check that the
caller either owns the booking or is Staff/Admin.

5. COMPLETE API REFERENCE
========================================================================

5.1 AUTH
POST   /api/auth/login
    Body: { "username": "", "password": "" }
    Errors: 400 missing fields, 401 invalid credentials, 403 deactivated

POST   /api/auth/reset-password   (any logged-in user)
    Body: { "old_password": "", "new_password": "" }
    Errors: 400 missing fields, 401 old password wrong, 404 user not found

5.2 PROFILE (any logged-in user)
GET    /api/profile
PUT    /api/profile
    Body (any of): { "email":"", "phone":"", "full_name":"", "address":"" }

5.3 STAFF MANAGEMENT (Admin only)
GET    /api/staff
POST   /api/staff
    Body: { "username":"", "password":"", "email":"", "id_type":"", "id_number":"", "phone":"" }
GET    /api/staff/<user_id>
PUT    /api/staff/<user_id>
    Body (any of): { "email":"", "id_type":"", "id_number":"", "phone":"", "password":"" }
PATCH  /api/staff/<user_id>/deactivate

5.4 MEMBERSHIP PLANS (Admin only)
GET    /api/membership-plans
PUT    /api/membership-plans/<plan_id>
    Body: { "price": 300 }

5.5 STUDENTS (mixed roles)
GET    /api/students                     (Staff or Admin)
POST   /api/students                     (Staff or Admin)
    Body: { "username":"", "password":"", "email":"", "full_name":"", "address":"", "plan_id": 1 }
GET    /api/students/<student_id>
GET    /api/students/<student_id>/verify   (Staff or Admin)
PATCH  /api/students/<student_id>/approve  (Admin only)
PATCH  /api/students/<student_id>/reject   (Admin only)
PATCH  /api/students/<student_id>/disapprove (Admin only)

5.6 STAFF STUDENT REGISTRATION (Story 1.3 - Staff or Admin)
POST   /api/staff/students/register
    Body: { "username":"", "password":"", "email":"", "full_name":"", "address":"", "plan_id": 1, "id_type":"", "id_number":"", "phone":"" }
GET    /api/staff/students/<student_id>

5.7 ADMIN MEMBERSHIP MANAGEMENT (Story 1.2 - Admin only)
GET    /api/admin/memberships/pending
GET    /api/admin/memberships  (optional ?status=Active)
POST   /api/admin/memberships/<membership_id>/approve
POST   /api/admin/memberships/<membership_id>/reject
PUT    /api/admin/memberships/<membership_id>
    Body (any of): { "plan_id": 2 } or { "extend_days": 30 } or { "membership_expiry": "2026-12-31" }

5.8 SEAT AVAILABILITY (Story 3.1 - any logged-in user)
GET    /api/seats/availability?date=YYYY-MM-DD&start_time=HH:MM&end_time=HH:MM
    Returns: list of free seats for that date/time slot.
    Errors: 400 missing/invalid params, 400 start_time >= end_time.

5.9 ADVANCE BOOKING (Story 3.2 - any logged-in user)
POST   /api/bookings
    Body: { "seat_id": 1, "date": "2026-08-10", "start_time": "10:00", "end_time": "12:00" }
    Returns: 201 with booking object including auto-generated checkin_code.
    Errors: 400 missing fields/bad format, 404 seat not found/inactive,
            409 seat already booked for that slot.

5.10 BOOKING MODIFICATION & CANCEL (Story 3.3 - owner, Staff, or Admin)
PUT    /api/bookings/<booking_id>
    Body (any of): { "date":"", "start_time":"", "end_time":"" }
    Errors: 400 bad format/invalid time range, 403 not authorized,
            404 booking not found, 409 new slot clashes with existing booking.

POST   /api/bookings/<booking_id>/cancel
    Body: none
    Returns: 200, booking status set to "Cancelled", seat freed.
    Errors: 400 already cancelled, 403 not authorized, 404 not found.

5.11 STUDENT BOOKING HISTORY (Story 3.4 - any logged-in user)
GET    /api/students/me/bookings
    Auth: jwt_required (any role).
    Returns:
      {
        "total_bookings": N,
        "bookings": [ { booking + seat_number } ... ]
      }
    Only bookings where booking.user_id == current user_id.
    Errors: 401 if not logged in.

5.12 DAILY BOOKING OVERVIEW (Story 3.5 - Staff/Admin)
GET    /api/staff/bookings/today
    Auth: staff_or_admin_required.
    Returns:
      {
        "date": "YYYY-MM-DD",
        "total_expected": N,
        "bookings": [
          {
            booking_id,
            seat_number,
            username,
            full_name,
            booking_date,
            start_time,
            end_time,
            status,
            checkin_code
          }
        ]
      }
    Only Confirmed bookings for today.
    Errors: 403 for Student or missing token.

5.13 WALK-IN ADMISSION (Story 3.6 - Staff/Admin)
POST   /api/staff/bookings/walk-in
    Auth: staff_or_admin_required.
    Body:
    {
      "student_id": <student_id>,
      "duration_minutes": 90   // optional, default 60
    }
    Behavior:
      - Validates student exists and membership_status == "Active".
      - Uses current time as start_time, end_time = now + duration_minutes.
      - Finds first active seat free for this slot.
      - Creates booking with auto checkin_code.
    Returns:
      {
        "message": "Walk-in booking created",
        "booking": { booking + seat_number + full_name }
      }
    Errors:
      400 missing student_id / bad duration_minutes,
      404 student not found or no seats configured,
      400 membership not Active,
      409 no free seats for current slot.

7. COMMON ERRORS AND FIXES
========================================================================

"Email is required" even though sent -> set Content-Type: application/json,
    Body tab set to JSON not Text.
401 Unauthorized on every request -> token missing/expired/no "Bearer " prefix.
403 not allowed -> wrong role's token used for that route, or trying to
    modify/cancel someone else's booking without Staff/Admin role.
sqlite3.OperationalError: no such column/table -> delete app.db, restart server
    (required after adding Seat/Booking models).
ModuleNotFoundError: No module named 'flask_cors' -> pip install -r requirements.txt.
git push rejected (fetch first) -> git pull origin dev, then push again.
409 Seat already booked -> expected behavior when double-booking same seat/date/overlap.
409 No free seats available right now -> expected when all seats are occupied.

11. WHY THIS STRUCTURE IS USED
========================================================================

The backend uses JSON request bodies with Flask request.get_json(), which
matches how modern frontend apps send API data. Flask-CORS is enabled on
/api/* routes so frontend code from a different origin can call the API
without browser CORS issues. Thunder Client is used for testing because
it supports collections, environments, request headers, auth, and
response testing directly inside VS Code.

The booking system checks overlapping time ranges using:
    existing_start < new_end AND existing_end > new_start
so partial overlaps are correctly blocked, while back-to-back bookings
are allowed.
