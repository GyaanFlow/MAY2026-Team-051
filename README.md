# Study Library Management System — Frontend

This repository contains the **frontend only** for the Study Library Management System (SLMS), served through a minimal Flask app. There is **no real backend/database** — a lightweight Flask server just renders the HTML pages, and all app data (seats, bookings, users, etc.) is generated by dummy/mock JavaScript data on the client side (`static/js/library-data.js`). Login does not validate credentials; it simply redirects you to a dashboard.

## Tech Stack

- **Server:** Python 3 + Flask (only used to serve HTML templates and static files)
- **UI:** Vue 3 (loaded via CDN, no build step / no npm required)
- **Styling:** Plain CSS (`static/css`)
- **Data:** Mock/dummy data defined in `static/js/library-data.js` (no database, no API calls)

## Prerequisites

- Python 3.8+ installed
- Internet access in the browser (Vue 3 is loaded from `unpkg.com` via CDN — no local install needed)

## Setup & Running Locally

1. **Clone / extract the project** and move into the folder:
   ```bash
   cd project
   ```

2. **(Recommended) Create a virtual environment:**
   ```bash
   python3 -m venv venv
   source venv/bin/activate      # Windows: venv\Scripts\activate
   ```

3. **Install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Run the app:**
   ```bash
   python app.py
   ```

5. **Open the app in your browser:**
   ```
   http://127.0.0.1:5000/
   ```

The server starts in debug mode by default, so it auto-reloads on file changes.

## Notes on the Dummy Backend

- The **login form does not check credentials**. Enter any username/password and it will redirect you to `/dashboard` (the student view). There's no logic yet to route staff/admin users to their respective dashboards based on role — you currently need to navigate to `/staff/dashboard` or `/admin/dashboard` directly in the URL bar to preview those views.
- All seat availability, bookings, history, and other data shown on the dashboards is **randomly/deterministically generated** in `static/js/library-data.js` for demo purposes — nothing is persisted, and refreshing the page regenerates state where applicable.
- There are `TODO` comments in the JS files (e.g. `static/js/auth.js`) marking where real API calls should eventually replace the mock logic once a backend is built.

## Troubleshooting

- **Port already in use:** Run `python app.py` with a different port, e.g. edit the last line of `app.py` to `app.run(debug=True, port=5001)`.
- **Blank/broken styling on dashboards:** Make sure you have an active internet connection, since Vue 3 is loaded from a CDN (`unpkg.com`) rather than bundled locally.
- **`ModuleNotFoundError: No module named 'flask'`:** Ensure your virtual environment is activated and you ran `pip install -r requirements.txt`.
